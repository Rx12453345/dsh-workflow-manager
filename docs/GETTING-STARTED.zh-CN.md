>
> English readers: see [USAGE.md](USAGE.md). This file exists because the rest of the
> repository is written in English, and the owner reads Chinese.

## 一、三十秒版：你只需要记住一句话

> **每个新项目，先说「初始化工作流」，再说「打开验证深度策略」。之后就不用管了。**

它会自动按你改的东西分配轻重：

| 你改了什么 | 它做什么 |
|---|---|
| 改文档、注释、说明 | **只跑一遍测试**（快，省 token） |
| 改普通代码 | 跑测试 **+ 变异测试**（慢一些，但更准） |
| **碰到审批、权限、安全** | **最严格，任何设置都改不了**（这是硬规矩） |

**所以你不是在「选快还是选准」——你打开它，它自己看着办。**

---

## 二、先理解：有两层设置

想象成「电脑的默认设置」和「某个文件夹自己的设置」：

| | 改在哪里 | 影响谁 |
|---|---|---|
| **默认值** | 设置 → 插件 → dsh-workflow-core | **所有工程** |
| **单个工程** | 在**那个工程里**说的话 | **只有那个工程** |

**你要的是第二种**——每个工程单独决定，互不干扰。

**最常见的困惑**：「我改了设置怎么没反应？」——因为你改的是**默认值**，而那个工程已经有自己的设置了。

## 三、你可以直接照抄的话

### 开始一个新项目
> **「初始化工作流」**

### 让它自动分配轻重（**最重要的一句**）
> **「打开验证深度策略，让它自己判断轻重」**

### 觉得它太慢 / 太费 token 时
> **「这次只是改文档，不用开评审代理，跑个测试就行」**

### 改动很重要时
> **「这次涉及安全，按最严格的来」**

### 不想要这套东西了
> **「这个工程不要用工作流」**

### 想看现在是什么状态
> **「看看现在工作流什么状态」**

## 四、什么项目用什么配置（按压力举例）

| 项目类型 | 建议怎么说 | 为什么 |
|---|---|---|
| **随手试验、学习用的脚本** | **什么都不说**，直接写 | 工作流不启用，零开销 |
| **纯笔记 / 文档仓库** | 「初始化工作流」+「打开验证深度策略」，然后**用最轻档** | 你只改文字，不该跑代码测试 |
| **你一个人的小工具** | 「初始化工作流」+「打开验证深度策略」 | 平时轻，改到关键处自动变严 |
| **要给别人用的、有测试的项目** | 上面这些 + 「及格线设 8 分」 | 有人用就得有验收标准 |
| **碰钱 / 权限 / 数据的东西** | 「用**严格**档」，**别关任何东西** | 安全类本来就不降级，关了也没用 |

**大多数情况下你只需要第三行的那两句。**

## 五、它会自己做什么（你不用管，但知道有好处）

四个你可能会注意到的机制：

- **干活的不能自己说完成** —— 必须有一个**新的**代理来打分。你看到「评审通过」才算真通过。
- **过程不占你的对话** —— 检查和打分都在**另外的**代理里发生，你的对话只收到结论。这正是这个东西存在的理由。
- **工具调用会被拦** —— 危险操作会先问你（或按你设的档位自动判断）。
- **它会记住教训** —— 反复出现的问题会记成「约束」，而且每条都带**什么时候可以作废**的条件。它**只会建议，不会自己删**。

## 六、出问题时的常用说法

| 现象 | 你可以说 |
|---|---|
| 太慢、太贵 | 「这个改动很简单，别开评审」 |
| 它老是问你 | 「审批改成模型自己判断」 |
| 它说评审没通过 | 「把评审说的问题修掉，然后再评一次」 |
| 你不想让它碰某个文件 | 直接说，「别改 X」 |
| 它卡在某个阶段 | 「看看现在卡在哪」 |

---

## 七、⚠️ 一个必须先做的一次性步骤

如果你刚开始用，**需要先让安装生效**：在插件目录里跑一次同步，然后重启 DSH。
（这一步只需要做一次；做之前「打开验证深度策略」那句话会报「未知配置键」。）
